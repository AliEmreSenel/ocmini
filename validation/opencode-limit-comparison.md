# OpenCode limits comparison

Compared on 2026-10-18 against [OpenCode v1.19.3](https://github.com/anomalyco/opencode/releases/tag/v1.19.3), pinned to commit `e3c4eb242585dcd77be1a867391b7c25fd47ce52`. v1.19.4 (published 2026-10-22) is the current latest 1.x release: it upgrades the bundled Bun runtime and build scripts and changes no part of the 1.x HTTP/SSE surface this compares. This primarily compares the 1.x runtime ocmini targets. ocmini values include this checkout's audit fixes and the subsequent requested parity updates. This is a source comparison, not a direct performance benchmark.

The upstream source contains a separate V2 core bash tool with a [ten-minute hard ceiling](https://github.com/anomalyco/opencode/blob/e3c4eb242585dcd77be1a867391b7c25fd47ce52/packages/core/src/tool/bash.ts#L19). The 1.x shell implementation allows larger explicit timeouts. Mixing these two implementations would give a misleading comparison.

The 100-step default and turn-wide compaction counters were additional ocmini restrictions and are removed. The requested parity updates also remove the 32 MiB text-file and 100,000-candidate ceilings, add compaction controls, switch searches to ripgrep, restore the web-fetch timeout ceiling, and increase provider retries to five. Two deliberate defaults differ: subagents permit eight nesting levels, and full-output expiry stays disabled unless explicitly enabled (`OCMINI_TOOL_OUTPUT_RETENTION_DAYS=7` enables seven-day startup expiry).

The generic `tool_output.max_lines` / `max_bytes` knobs and progress-resetting MCP deadlines remain gaps; they were outside this parity update. Read-page limits and compaction controls are implemented. ocmini counts Unicode scalar characters for its line cap, preserving valid UTF-8; JavaScript's upstream string slicing counts UTF-16 code units.

Sources were fetched from the pinned release. Absence claims above refer to the named implementations, not every provider, operating system, attachment pipeline or V2 runtime. The prior stress-test report measures two ocmini builds and does not establish a speed or memory advantage over OpenCode.
